# 00 · 我的电脑能"听见"机器人吗？

**带走的一句话**：连上机器人 = 同一种 DDS（CycloneDDS）+ 同一个 Domain（0）+ 走对网卡。

## 演示顺序（45 分钟）

| 时间 | 做什么 | 停在哪 |
|---|---|---|
| 0–5 | 讲 `LIVE` 开关：没真机时数据从哪来（回放 bag，合成），指令去哪（只打印） | 第一格 |
| 5–15 | 运行 `ros2 topic list -t`、`topic_table()`、`echo --once` | 表格出来后停：让学生指出哪些是"状态"、哪些成对 |
| 15–28 | 三个条件逐个看：环境变量、Domain、XML 文件；讲 `rt/` 前缀 | 打印 XML 后停：问"网卡名在哪一行" |
| 28–36 | 改坏：Domain 改 1；网卡名写错 | 两次都先让学生预测"看不到"还是"报错" |
| 36–43 | 换 G1：对比 Topic 表和两种 `LowState` | 让学生自己找不同，写在纸上（01 节要用） |
| 43–45 | 小结 + 真机连接步骤口头过一遍 | |

## 课堂提问

1. **`/api/sport/request` 和 `/api/sport/response` 成对出现，你猜它们是干什么的？**
   一问一答：往 request 发请求，从 response 收应答，这是 Unitree 高层接口的实现方式（05 节揭晓）。此处只要学生猜到"像函数调用"即可。
2. **Domain ID 改成 1 以后只剩两个 Topic，而网卡名写错却直接报错。为什么症状不一样？**
   Domain 不对时 DDS 本身工作正常，只是"进错了房间"，所以安静地什么都看不到；网卡不存在时 DDS 连域都建不起来，在初始化阶段就失败。
3. **Go2 和 G1 的 `/lowstate` 名字一样，类型不一样。如果用 Go2 的类型去订阅 G1 会怎样？**
   收不到任何数据且不报错（Topic 名和类型都一致才算同一个 Topic）。这是 05、12 节的伏笔，这里让学生先猜，不给结论也可以。

## 常见误解

- **"离线模式是假的，学了没用。"** 回放的 bag 走的是和真机完全相同的 DDS 通路、相同的 Topic 名和消息类型，只是数值是合成的。代码不改一个字就能连真机——这一点要在第一节讲透。
- **"`rt/lowstate` 和 `/lowstate` 是两个 Topic。"** 是同一个；`rt` 是 ROS 2 在 DDS 层自动加的前缀。
- **VMware 用 NAT 模式也能连。** 不能。DDS 的发现依赖组播，NAT 下虚拟机和机器人不在同一个二层网络。必须桥接到连机器人的那块物理网卡。
- **装了 ROS 2 就能连 Unitree。** ROS 2 Humble 默认的 RMW 是 FastDDS，必须切到 CycloneDDS（`scripts/env.sh` 已经做了）。

## 承上启下

- 这是第一节，承的是安装（`scripts/install.sh`）。上课前让学生在自己机器上跑完安装并 `source scripts/env.sh`。
- 留给 01 的钩子：`LowState` 里有上百个数——"它现在站没站稳？"

## 课后作业与参考解

1. **连不上时检查的三样东西**：`echo $RMW_IMPLEMENTATION`（应为 `rmw_cyclonedds_cpp`）；`echo $ROS_DOMAIN_ID`（0）；`echo $CYCLONEDDS_URI` 并打开那个 XML 看网卡名，再 `ip addr` 确认该网卡有 `192.168.123.x` 地址。
2. **量频率**：`ros2 topic hz /lowstate`。回放数据约 200 Hz；让学生记下来，14 节会和真机标称值对照。
