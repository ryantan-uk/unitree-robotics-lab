# 17 · 画一张地图，再问"从这儿到那儿怎么走"

**带走的一句话**：地图只记录了看到的——没看到不等于没有。

## 课堂提问

1. **回放数据建图为什么必须 `--clock` 加 `use_sim_time:=true`？**
   激光的时间戳是录制时的；slam_toolbox 要查"那一刻"的 `odom → base_link`。若节点用墙上时钟，TF 的时间戳是今天的，和激光对不上，每一帧都会被丢弃。
2. **目标 B 直线不到 4 m，路径也只有 4.3 m，但它不是直线。它为什么不贴着隔墙的端点走？**
   规划用的是代价地图：障碍物先按 `robot_radius`（0.35 m）膨胀为不可通行，再向外按 `inflation_radius`（0.55 m）加一圈衰减的代价。路径被"推离"墙面。
3. **目标 C 在箱子里，为什么规划成功了？**
   箱子内部和背面激光照不到，在地图上是"未知"而不是"占据"；配置里 `allow_unknown: true`。规划器从还没被看到的那一面进去了。结论：地图的"未知"不等于"空闲"；要不要允许穿越未知区域是一个安全决策。

## 常见误解

- **"SLAM 输出的是机器人的位置。"** 它输出两样：地图，以及 `map → odom` 的修正量。机器人在地图里的位置 = `map → odom` × `odom → base_link`。
- **"里程计准的话就不需要 SLAM。"** 这段合成数据的里程计没有漂移，所以 `map → odom` 接近零；真机腿式里程计走几十米会漂几十厘米，靠 SLAM 拉回来。
- **"规划出路径就等于会导航。"** 规划只是 Nav2 的一环；跟踪路径（controller）、遇阻重规划、恢复行为都还没涉及，且需要机器人真的会动。本课程只验证到规划。
- **"栅格值 0～100 是概率，50 是分界。"** 在 slam_toolbox 的输出里基本只有 −1 / 0 / 100 三种值。
- **G1 的 `/utlidar/cloud`** 是合成数据沿用 Go2 的名字，真机 G1 的雷达 Topic 需自己确认。

## 课后作业与参考解

1. **`allow_unknown: false`**：第 5 秒时地图大部分未知，去 A 的规划失败；第 30 秒时成功。同时目标 C 会变成失败（箱子内部未知）。
2. **`inflation_radius` 0.2 / 0.55 / 1.0**：0.2 时路径贴着隔墙端点拐弯（真机稍有定位误差就会蹭到）；1.0 时路径离隔墙端点更远、拐得更缓、总长更长。隔墙端点到对面外墙有 4.1 m，通道很宽，所以不会走不通；若通道宽度小于 2 ×（`robot_radius` + 余量），过大的膨胀会让规划器宁可绕远甚至失败。
3. **`map_to_png`**：`img = np.where(a < 0, 205, np.where(a > 50, 0, 254)).astype(np.uint8)`，**上下翻转**后保存（图像原点在左上，地图原点在左下）；yaml 写 `image`、`resolution: 0.05`、`origin: [x0, y0, 0.0]`、`negate: 0`、`occupied_thresh: 0.65`、`free_thresh: 0.25`。
