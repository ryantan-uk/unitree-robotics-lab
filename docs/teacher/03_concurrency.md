# 03 · 几路数据同时来，怎么一个都不耽误？

**带走的一句话**：单线程执行器里，一个慢回调会饿死所有回调；多线程执行器要和回调组一起用。

## 课堂提问

1. **单线程时"最长一次没收到 lowstate"为什么约等于 150 ms？**
   执行器一次只跑一个回调。点云回调睡 150 ms 期间 lowstate 在队列里排队，队列只有 10 个位置，排不下的被丢弃；回调返回后才继续处理。
2. **线程数加到 3 但没分回调组，为什么没用？**
   默认所有回调都在同一个 `MutuallyExclusiveCallbackGroup` 里，组内互斥，线程再多也只能一个一个来。
3. **什么情况下"工作线程 + 只留最新"比"回调组"更合适？**
   处理比数据到达还慢的时候。回调组方案里每帧都要处理，会越积越多；只留最新的方案自动跳帧，处理的永远是最新数据。

## 常见误解

- **"Python 有 GIL，多线程没意义。"** GIL 只限制纯 Python 的 CPU 计算并行。等待 I/O、`time.sleep`、NumPy 运算、rclpy 的底层调用期间都会释放 GIL，所以对"回调互不阻塞"这个目标完全有效。
- **"都放进 `ReentrantCallbackGroup` 最省事。"** 同一个回调可能被两个线程同时执行，回调里改的每个变量都要加锁。能用互斥组分开就不要用可重入组。
- **"`asyncio` 比线程快。"** 它不是为了快，是为了在一个线程里同时**等**很多件事。有 CPU 活要干时没帮助。
- **实测数字会随机器变。** 提醒学生：重要的是"尖刺有没有"，不是具体多少毫秒。

## 课后作业与参考解

1. **队列容量 100**：每帧处理 0.3 s、每 0.2 s 来一帧，队列每秒净增约 1.7 帧；20 秒后队列里约 33 帧，正在处理的那帧大约是 6～7 秒前收到的。"队列大更安全"错在：它把"丢数据"换成了"用旧数据"，后者更隐蔽。
2. **1 Hz 定时器**放在"快"的那组（或单独一组）即可；绝不能和点云回调同组，否则打印会被拖住。
3. **超时**：
   ```python
   try:
       r = await asyncio.wait_for(ask("sport", 0.3), timeout=0.2)
   except asyncio.TimeoutError:
       r = "sport: timeout"
   ```
