# 11 · 直接指挥每一个电机：位置、速度、力矩

**带走的一句话**：一条控制律 τ = kp·(q_des − q) + kd·(dq_des − dq) + τ_ff；振荡、力矩尖峰、稳态误差都能从它读出来。

## 课堂提问

1. **目标平滑时 `kd=0` 和 `kd=1` 看不出区别，那为什么还要 `kd`？**
   平滑目标几乎不激发振荡，把坏增益藏了起来。一旦有扰动或目标跳变（第 4 列），没有阻尼就长时间振荡。调增益时要故意加小阶跃"敲一敲"。
2. **`kp=60`，关节要持续出 6 N·m 的力，稳态误差是多少？怎么消掉？**
   纯 PD 下力矩只能来自误差：6 / 60 = 0.1 rad。消除办法：把已知负载填进 `tau`（前馈）。加大 `kp` 也能减小，但更硬、更易振荡、碰撞更危险。
3. **循环实际周期 4 ms 而不是 2 ms，会带来什么后果？**
   按"拍数"推进的轨迹变慢一倍（3 秒的动作做了 6 秒）；偶发的几十毫秒卡顿期间电机按旧指令出力。所以目标必须平滑、时间应取真实时钟、严格实时的控制用 C++ 并在机载电脑上跑。

## 常见误解

- **"位置控制、速度控制、力矩控制是三种模式，要切换。"** 是同一条式子里哪几项非零。纯力矩控制 = `kp = kd = 0`。
- **"CRC 错了会报错。"** 机器人直接丢弃，无任何反馈（这是 SDK 和协议的通常做法；丢弃行为本身在三个仓库里看不到，属真机待验）。
- **"`mode_machine` 填 0 就行。"** 必须从 `LowState` 读回来再填；官方示例在读到之前一条指令都不发。
- **"第一条指令的目标可以是零位。"** 必须是当前位置，否则就是一次阶跃。
- **"Go2 和 G1 的 `LowCmd` 通用。"** 类型、初始化方式、CRC 打包长度都不同（见对比表）；相同的是控制律和 Topic 名 `rt/lowcmd`。
- **合成数据的力矩很小（0.1 N·m 量级）**：因为模型里的关节惯量是随手取的。只看形状和相对关系，不看绝对值。

## 课后作业与参考解

1. **`kp=120` 无前馈**：误差 = 6 / 120 = 0.05 rad。不这么做是因为刚度翻倍后系统更接近振荡边界，且碰到障碍时力矩上升更快。
2. **纯阻尼**：`kp=0, kd=3, tau=0`（`q`、`dq` 填 0 即可）。对应 09 节的 Damp。低层程序退出前发它，是为了让关节缓慢下落而不是突然失力（零力矩）或保持最后一个可能很别扭的位置。
3. **删掉 CRC**：离线运行不报任何错。说明这类错误只能靠**对端的反馈**发现——机器人没动、或者像 10 节那样把发出去的指令录下来检查。
4. **按真实时间走**：`t = time.monotonic() - self.t_start; q_des = interpolate(q0, goal, t, duration)`。重跑后动作用时等于 `duration`，只是轨迹上的采样点变稀。
