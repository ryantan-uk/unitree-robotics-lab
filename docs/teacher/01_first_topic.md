## 课堂提问

1. **只看 roll、pitch 能不能判断站没站稳？**
   不能。趴着时机身也是水平的（图上全程 ±2°）。必须加"是否撑着体重"——Go2 用四脚足端力之和。
2. **走路时单只脚的力会掉到 0，为什么判据还成立？**
   判据用的是四只脚的**和**。小跑时对角两只脚轮流支撑，总和始终约等于体重。
3. **回调慢、队列深度从 1 加到 100，收到的条数几乎没变，为什么？**
   队列只是"暂存"，不会让你处理得更快。处理速度是每条 20 ms，无论队列多深每秒都只能处理约 50 条；队列深只意味着你处理的是更旧的数据。

## 常见误解

- **"订阅了就会自动收到。"** 回调只在节点被 spin 时执行。这是最常见的"没数据"原因，值得现场把 `spin_for` 注释掉演示一次。
- **"QoS 不匹配会报错。"** 不会，只有一条 WARN 日志（且只在发现时打印一次），之后静默收不到。
- **"队列调大就不丢消息。"** 见提问 3。对控制而言旧数据比没数据更危险。
- **"`foot_force` 的单位是牛顿。"** 是传感器原始读数；合成数据里站立约 55/脚，真机数值不同。阈值必须在真机上重新读。

## 课后作业与参考解

1. **`g1_is_standing`**：
   ```python
   def g1_is_standing(roll, pitch, knee, tilt_max=15.0, knee_max=1.0):
       tilt = np.degrees(np.arccos(np.cos(roll) * np.cos(pitch)))
       return (tilt < tilt_max) & (knee < knee_max)      # 蹲着膝角约 2.4，站直约 0.3
   ```
2. **阈值 150 / 30**：150 时站立静止（约 220）仍判为站立，但余量变小，足端力读数稍低就误判成"没站稳"；30 时趴下过程中的残余读数也会被判成站立。真机上宁可误判成"没站稳"（保守：停下来）。
3. **用 `position[2]`（机身高度）更简单**，隐患是它是运动服务**估计**出来的量：服务没启动、估计器漂移时不可信；而足端力和 IMU 是原始测量。
