## 课堂提问

1. **`robot_state_publisher` 的输入和输出各是什么？**
   输入：URDF（参数 `robot_description`）和 `/joint_states`。输出：`/tf`（每个活动关节对应的父→子变换）和 `/tf_static`（固定关节）。它做的事就是正运动学。
2. **桥发布的是 `odom → base_link`，URDF 的根是 `base`。这两棵树怎么接上？**
   launch 里有一个恒等的静态 TF `base_link → base`（G1 是 `base_link → pelvis`）。少了它，TF 会分裂成两棵互不相连的树，RViz 里模型和里程计对不上。
3. **点云里的墙在 RViz 里斜着插进地面，最可能是什么问题？**
   雷达外参（`base_link → utlidar_lidar`）不对，尤其是旋转部分。Go2 的雷达是倾斜安装的，课程默认值只有平移，是合成数据用的。

## 常见误解

- **"URDF 里有机器人的当前姿态。"** 只有几何和约束；姿态来自 `/joint_states`。
- **"关节角顺序对就行，名字无所谓。"** `robot_state_publisher` **只按名字**匹配，顺序无所谓、名字必须对。改坏实验里顺序没变、名字错位，结果就是骨折。
- **"没有网格文件模型就没法用。"** TF 的计算完全不需要网格。本课程的无界面验证（火柴人）就是证明。
- **"TF 查询返回的是我请求时刻的变换。"** `Time()` 表示"最新可用的"。回放时若不开 `use_sim_time`，按具体时间戳查询会失败。
- **Go2 的 URDF 里连杆比你想的多**（42 个）：有 rotor、foot、雷达、IMU 等固定连杆。

## 课后作业与参考解

1. **轴距 / 轮距**：`position("base","FR_foot")[0] - position("base","RR_foot")[0]`；`position("base","FL_foot")[1] - position("base","FR_foot")[1]`。站立静止时取值（行走中四只脚前后位置在变）。
2. **`body_height_from_tf`**：`-np.mean([position("base", f)[2] for f in FEET])`。与 `position[2]` 相比：站立时接近；趴下时 TF 算的是"脚在机身下方多少"（约 0.10），而机身实际离地更低——两者定义不同，这是好的讨论点。
3. **Fixed Frame 改成 `base_link`**：机器人固定在画面中央不动，房间（点云、地图）反过来绕着它移动。Fixed Frame 决定"谁是静止的参考"。
